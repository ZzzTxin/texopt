## 0　先懂三件事，后面全通

**第一件：TeX 里有两种盒子。**
- 横着的叫 `hbox`，就是**一行字**。
- 竖着的叫 `vbox`，就是**一页东西**（页面上的内容块往上堆）。
日志里说的 overfull/underfull，都是这两类盒子的"尺寸不合适"。

**第二件：日志是唯一说实话的地方。**
PDF 看起来没问题，不代表 TeX 没在里面硬撑。比如一行字超出版心 5pt，PDF 照样能出，但日志会记一笔 `Overfull \hbox (5.0pt too wide)`。所以"缺陷"这件事只能从编译日志数，不能从 PDF 目测。

**第三件：像素是第二说实话的地方。**
日志不知道"这一页看着空不空"，那要靠把 PDF 渲染成图，数黑白像素。我们渲染成 40 dpi 的灰度图（A4 一页约 340×440 像素），灰度低于 200 的像素算"有墨"，其余算"白纸"。

### 1.4　缺陷计数（9 项，这一节最重要）

先记住单位：**1 pt ≈ 0.35 mm**。日志里 `(4.19pt too wide)` 就是"超出约 1.5 毫米"。

#### ① `overfull`（行溢出 / 内容戳出版心）
- **是什么**：TeX 排好一行，发现内容比版心还宽，右边戳出去了。常见于长 URL、长公式、无法断行的英文单词、`\includegraphics` 太宽。
- **日志长这样**：`Overfull \hbox (4.19pt too wide) in paragraph at lines 407--419`
- **我们量到**：出现率 **71.0%**（200 篇里 142 篇至少一处），篇均 **4.88** 处，每 10 页 **25.1** 处，有的最多 **122** 处。
- **怎么看**：这是"录用稿里也很常见"的缺陷。所以它不能用"有没有"来判，只能看**多不多**、**多严重**（见 1.5 的幅度）。

#### ② `underfull`（行欠满 / 字间距被拉稀）
- **是什么**：一行内容太少，TeX 不肯断行，只好把字与字之间的空隙拉开、把单词间距撑大，看起来"稀稀拉拉"。
- **日志长这样**：`Underfull \hbox (badness 10000) in paragraph at lines 88--92`
- **我们量到**：出现率 **73.5%**，篇均 **11.40** 处，每 10 页 **58.5** 处，最多 **150** 处。
- **怎么看**：比 overfull 还常见约 2.3 倍。**这条数据直接质疑现在权重**——现在 `underfull` 权重 0.6，`overfull` 1.0，方向对，但 if 按频率反推，两者差距应该更大。

#### ③ `vbox_over`（页盒溢出 / 一页塞不下）
- **是什么**：这一页的内容比页面高度还高，TeX 硬挤进去（可能压到底边线、或把最后一段推走）。
- **日志**：`Overfull \vbox (3.36pt too high) detected at line 319`
- **我们量到**：出现率仅 **14.5%**，篇均 0.44 处，最多 34 处。
- **怎么看**：**这是稀有缺陷**——85% 的录用稿一次都没有。按"越稀有越不可接受"的逻辑，它的权重应该是 P 里最高的那一档，可现在只有 1.0。

#### ④ `vbox_under`（页盒欠满 / 一页没填满）
- **是什么**：这一页的内容不够高，TeX 把页内的垂直间距（段间距、公式间距）拉开去凑满，看起来"页面被抻长了"。
- **日志**：`Underfull \vbox (badness 10000) has occurred while \output is active`
- **我们量到**：出现率 **79.0%**，篇均 **4.55** 处，最多 40 处。
- **怎么看**：**近八成录用稿都有**。这是最常见的一类"页面没填满"，几乎等于排版常态（章节末尾、图挤走正文都会造成）。现在权重 1.4（第二高）**方向很可能反了**。
- **额外发现**：它的 badness 值 P50 就已经是 10000（顶格），也就是"要不不报，一报就是最丑"，这个指标没有中间档次。

#### ⑤ `floatwarn`（浮动体警告）
- **是什么**：图/表这类"浮动体"本该由 TeX 自动找位置，但它被迫改了你的要求。典型几种：
  - `LaTeX Warning: Float too large for page by 12pt` —— 图比一页还高
  - `LaTeX Warning: 'h' float specifier changed to 'ht'` —— 你要求"就地放"，TeX 不干
  - `LaTeX Warning: Too many unprocessed floats` —— 图堆在一起排不下
- **我们量到**：出现率 **47.0%**，篇均 1.97，最多 29。
- **怎么看**：这就是"浮动体错位"的直接证据，属于**硬伤类**，但接近半数录用稿也有——说明轻度错位可容忍，严重错位（图比页高、堆图）才致命。

#### ⑥ `warn`（其它警告）
- **是什么**：除浮动体以外的 `LaTeX Warning`，已按文本去重。
- **我们量到**：篇均 **78.9** 条。这个数看着吓人，其实主要是 `Reference 'fig:framework' on page 3 undefined`（交叉引用第一次编译没解析到，第二遍就好）以及 `Unused global option(s)`。
- **怎么看**：**这类需要先分类再谈权重**，现在混在一起统计没意义，所以这一步只存了前 5 条样本，没做分析。这是 Step 2 的活。

#### ⑦ `errors`（真错误）
- **是什么**：`! LaTeX Error: ...`，编译报错。
- **我们量到**：200 篇里只有 1 篇 1 条，其余全是 0。
- **怎么看**：arXiv 上的东西大多能编过；这条数据基本没信息量，但保留着以防以后跑扰动版时突然变多。

#### ⑧ `macros_missing`（质量宏缺失）
- **是什么**：日志里有没有 `microtype` 的痕迹。`microtype` 是个开箱即用的宏包，专门做"字距微调 + 断字优化"，装上就能少一堆 overfull/underfull。
- **我们量到**：**56.0% 的录用稿没用 microtype**。
- **怎么看**：现在 P 里"质量宏缺失"权重是 **2.0，全场最高**。但一半录用稿都没用它 —— 按这个口径，一半正常论文直接吃 2.0 分。这条要么大幅降权，要么改成"用户明确要求了才计"。

#### ⑨ `float_H`（强制就地放置 `[H]`）
- **是什么**：源码里写 `\begin{figure}[H]` 的比例，它会让图"钉死"在当前位置，容易造成大留白。
- **我们量到**：显示 0 —— **但这是我这边的 bug**：我把这个数在**日志**上数的，而 `[H]` 只会写在**源码**里，日志里不会出现。这条要在 Step 2 重数（从 `.tex` 里数）。

### 1.5　缺陷幅度（比"有没有"更关键的一层）

`amplitude` 这一组不是"几处"，而是"**每处有多严重**"。

| 字段 | 大白话 | 实测 |
|---|---|---|
| `raw_overfull_pt_max` / `_mean` / `_all` | 这篇所有行溢出里最大/平均/全量的超出量（pt） | 全语料 977 处：P50 **4.19 pt**（约 1.5 mm，勉强看得出）、P90 **16.4 pt**（约 5.7 mm，肉眼明显）、最大 **269 pt**（约 9.5 cm，等于整行/整图戳出页面） |
| `raw_vbox_pt_max` | 页盒溢出的最大高度 | 88 处：P50 2.79 pt、P90 13.1 pt、最大 49.4 pt |
| `raw_underfull_badness_max` | 行欠满的 badness 最大值 | badness 范围 0–10000，越大字间距越离谱 |
| `perceive_overfull` / `perceive_underfull` / `perceive_vbox` / `perceive_floatwarn` / `perceive_warn` | **同一件事用旧代码口径再数一遍**，用来对照 | overfull 旧口径 323 条 vs 新口径 361 条 → 旧代码**漏检 10.5%** |

> 为什么要两套口径并存：旧代码 `perceive.parse_log()` 只认 `in paragraph at lines`，会漏掉 `detected at line N`（公式/盒子里的溢出）。这不是可有可无的细节——公式溢出恰恰是最难看的那类。

### 1.6　页面像素指标（11 项，model2 的原料）

全部是"占页面的比例"，0 到 1 之间。

| 字段 | 大白话 | 实测（200 篇 3898 页） | 怎么读 |
|---|---|---|---|
| `ink_ratio` | 这一页有多少比例的面积被墨占了 | P50 **0.120**、P95 0.209、最大 0.568 | 0.12 = 纸面 12% 有墨。>0.2 偏黑（图多/字挤），<0.06 偏淡（页面空） |
| `top_blank` | 从页面最顶往下多高才开始有内容 | P50 **0.079**、P95 0.118 | 0.079 = 顶部 7.9% 是白边（含页眉留白） |
| `bottom_blank` | 页面最底往上多高是空白 | P50 **0.066**、P95 0.161、最大 0.866 | 大 = 页底一大片白，是"留白异常"的主指标 |
| `content_height` | 真正有内容的纵向长度占页高 | P50 **0.848** | 0.85 = 内容占 85% 页高，剩下的是上下白边 |
| `max_gap` | 页内最长的一段连续空白有多高 | P50 **0.100**、P95 0.344 | 0.10 是正常的段间 + 图旁空白；0.34 = 页面中间被挖了个大洞 |
| `max_gap_at` | 这个洞开在页面的什么位置（0=页顶，1=页底） | — | 用来区分"章节末尾自然留白"（靠页底）和"图文错位挖洞"（页面中部） |
| `band` | 页面上"最厚的一块实在内容"有多高 | P50 **0.004**、P95 0.055 | 定义是"连续多少行的墨迹≥行宽 50%"，本意抓大图/大表块 |
| `band_at` | 这块内容在页面什么位置 | — | 配合 `band` 看是"顶天立地一张大图"还是"夹在文字里的表" |
| `left_blank` | 页面左侧多宽完全没墨 | P50 **0.091** | 本质就是左边距占页宽的比例 |
| `right_blank` | 页面右侧多宽完全没墨 | P50 **0.115** | 右边距；左右不等说明版心没居中 |
| `top_bottom_ratio` | 上半页墨量 ÷ 下半页墨量 | P50 **1.031**、P95 3.758、最大 10011 | 1.0 = 上下一样重，看着舒服；>2 = 上重下轻；10011 是下半页几乎全白导致的除法爆表 |

**关于 `band` 为什么实测这么小（P50 只有 0.004）——这是最重要的一个发现。**
它的判据是"一整行里有 50% 以上的宽度是墨"。但 40 dpi 下，一行正文的墨覆盖率通常只有 30–40%，一张普通折线图更浅。于是几乎没有任何行能过 50% 这道线，`band` 基本恒为 0。**也就是说这个指标现在测的不是"图表占比"，而是"有没有一行全黑的横条"**。现在 `SOFT_BANDS` 给它定的理想带是 (0.05, 0.35)，比实测中位数大 12 倍，导致 94.7% 的正常页被判"低于下界"，然后按"低偏罚更重"的规则每页都吃罚分。这不是权重问题，是**指标定义坏了**。

## 2　表 2 六个分析项逐个说明

### 2.1　论文规模
**问的是**：这批语料到底多长？
**怎么算**：把 200 个 `pages` 排成一队，取各分位点。
**结论怎么用**：定了"缺陷归一化"的分母（每 10 页），也暴露了"126/200 超 target_pages"这件事——页数 gate 不能直接拿 bench 的 target 当红线。

### 2.2　缺陷频率
**问的是**：这些缺陷在"已经发表的论文"里有多常见？
**三个数各有分工**：
- **出现率**（多少篇至少有一处）：回答"这个毛病是不是普遍存在"。普遍存在 → 社区容忍 → 权重该低。
- **篇均**（平均每篇几处）：回答"一般要修几处"。
- **每 10 页**：回答"密度"，把长论文和短论文拉到同一把尺子上比较。
**结论怎么用**：这是 `wᵢ = 严重度ᵢ ÷ 频率ᵢ` 里的**分母**，也就是"会议容忍度"。它**不能**单独定权重——严重度还得另找来源。

### 2.3　缺陷幅度
**问的是**：同一个缺陷，程度差多少？
**为什么必须有**：现在的 P 是 `Σ wᵢ × Nᵢ`，也就是"4pt 的溢出"和"269pt 的溢出"各算 1 处。实测 P50 是 4.19pt、最大 269pt，**差了 64 倍**，线性计数等于把这个差别抹平了。
**结论怎么用**：要么按幅度加权（比如按 `log(1+pt)`），要么先加一条饱和曲线 `1−exp(−n/τ)`，τ 用计数分布的 P50/P90 定。

### 2.4　软指标分位
**问的是**：正常论文的页面，"灰度/留白/占比/均衡"落在什么范围？
**怎么算**：3898 页每页 11 个指标，各取分位。
**结论怎么用**：这是 `A_soft` 理想带的**唯一有据来源**。比如 ink_ratio 的 P10–P90 是 0.057–0.173，那么"理想带"设在 (0.05, 0.20) 附近才叫合理，而不是现在拍的 (0.02, 0.15)。

### 2.5　现有带命中率
**问的是**：现在写死的这些理想带，到底把多少正常页判成了异常？
**怎么算**：拿 3898 页逐一对 `SOFT_BANDS` 判定"低于下界 / 带内 / 高于上界"。
**结果**：
- `ink_ratio` 22.2% 的页"太黑"
- `max_gap` 18.6% 的页"洞太大"
- `top_bottom_ratio` 20.0% 的页"上下不均衡"
- `left_blank` / `right_blank` 各约 10.7% 越界
- `band` **94.7% 低于下界**（见 1.6 的解释）
**结论怎么用**：一个指标如果把 20% 的正常页判成异常，它不是"严"，是"错了"。这批数就是改带的直接依据。

### 2.6　卫生与工程
**问的是**：几项工程性指标（质量宏、`[H]`、编译耗时）在真实语料里啥情况。
**结论**：microtype 缺失 56%（说明"质量宏缺失"这条现在权重 2.0 太狠）；`[H]` 那个数是我数错了（要从源码数）；编译中位 38 秒（决定了以后批量跑的成本）。

## 4　几个统计说法的大白话解释

| 说法 | 大白话 |
|---|---|
| **均值** | 加起来除以篇数。会被极端值带偏（比如 overfull 有个 269pt 的），所以看均值的同时要看分位 |
| **P50（中位数）** | 把所有值排成一队，站正中间那个。比均值抗极端值 |
| **P10 / P90** | 排在第 10% / 90% 位置的值。P10–P90 之间 = "80% 的正常论文都在这条带里" |
| **出现率** | 200 篇里有几篇至少犯一次，除以 200 |
| **篇均** | 总次数 ÷ 篇数 |
| **每 10 页** | 总次数 ÷ 总页数 × 10。把长短论文拉到同一把尺子 |
| **非零篇 P50** | 只在"犯过这个错的那些篇"里算中位数，回答"犯起来一般犯几处" |
| **顶格比例** | badness 封顶 10000 的占比。顶格 = TeX 已经放弃治疗 |
| **带内 / 越界** | 拿现有理想带做尺子，把语料的页分成"太淡/正常/太过"三堆 |
| **pt** | 排版单位，1 pt ≈ 1/72 英寸 ≈ 0.35 mm。10pt 就是 3.5 mm，肉眼可见的戳出 |

---

## 5　这一步确认的三个 bug（都要在 Step 2 修）

1. **`Underfull \vbox` 的正则写错**：它报的是 `(badness N)`，不是 `(Npt too short)`。我第一版按后者写，导致 `vbox_under` 一度全 0；改了之后是 79% 的篇都有。教训：报数之前先看一眼原始日志的字符串形态。
2. **`perceive.parse_log()` 漏检 overfull**：只认 `in paragraph at lines`，漏掉 `detected at line N`（公式/盒子里的溢出），漏检率 10.5%。这类恰恰是最难看的那种。
3. **`band` 指标定义失效**：50% 行宽墨迹的判据在 40 dpi 下几乎无人能过，实测 P95 只有 0.055，与理想带 (0.05, 0.35) 差 1–2 个数量级。
4. **报告标签错误**：`tools/corpus_analyze.py` 生成的报告里软指标表头写的是 "P5"，实际取的是 P10。
   数值本身没错，标签已在该工具的模板里修正。

## 6　术语速查

| 词 | 意思 |
|---|---|
| `hbox` | 横盒子，一行内容 |
| `vbox` | 竖盒子，一页内容块 |
| overfull | 内容超出容器，戳出去 |
| underfull | 内容不足，容器被硬撑开（间距拉大） |
| badness | TeX 给"这一行/这一页有多勉强"打的 0–10000 分，10000 是顶格（最丑） |
| 浮动体 float | 图、表这类 TeX 自己有主意的对象 |
| `[H]` | 用户强令"就放这儿"，不给 TeX 挪动的余地 |
| `microtype` | 一个宏包，做字距微调与断字优化，能显著减少 overfull/underfull |
| dpi | 渲染分辨率，40 dpi 表示一英寸画 40 个点，A4 一页约 340×440 像素 |
| PGM | 一种最简单的灰度图格式（`P5` 二进制），只存每个像素的灰度值 |
| 墨（ink） | 灰度 < 200 的像素。我们的判"墨"阈值，比纯黑（0）宽松，能抓住抗锯齿后的字 |
| 版心 | 页面里真正排字的区域，边距之外的部分 |
| target_pages | bench 给的会议页数预算，来自 camera-ready，不等于 arXiv 版长度 |
