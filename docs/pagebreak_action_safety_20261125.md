# 修改层：结构分页保护（2026-11-25）

问题由 OpenSTL 实际案例复现：旧 `remove_manual_pagebreak` 一次删除正文中全部
`newpage`、`clearpage`、`pagebreak`，没有区分附录另起页、图表冲刷与普通正文分页。
后续评分可能奖励命令减少，却没有识别图文关系变差。因此，这次先将边界落实到
**动作自身**，不依赖修改先发生、评分再拦截。

## 现在允许修改什么

`texopt/actions.py:remove_manual_pagebreak` 每次只尝试一处独占一行的
`newpage` 或强制 `pagebreak`。相邻内容必须可确认为普通正文，随后仍走整篇编译验收。
其他符合条件的分页需要下一次调用重新判断，禁止一次批量删除。

下列情况直接保留，不进入候选修改：

- `clearpage`、`cleardoublepage`：保留冲刷待排图表及左右页语义。
- 章节、标题、目录、参考文献、附录等结构边界及附录/参考文献区域。
- 环境、分组、宏参数、条件分支、数学与代码示例内部。
- 前方已有图表、外部 `input` / `include` 或未知宏：源码不能确定浮动体是否仍在排队。
- 非强制 `pagebreak[0..3]`、行内组合命令及无法确认的上下文。

这是保守的源码边界，可能保留一些实际可取消的分页；不会假装完成了完整的 TeX
宏展开或待排浮动体队列分析。需要更复杂的结构重排时，不能绕过此动作直接改原稿。

规则候选和模型白名单都调用同一个动作，保护在两条路径中一致生效。白名单说明、
候选提示与 advisory 同步改为先判断用途，不再宣称手动分页必然破坏布局。
检测的缺陷种类、P 权重和 M1/M2 验收公式本轮未改。
