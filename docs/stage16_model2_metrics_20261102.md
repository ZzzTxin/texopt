# 阶段 16：model2 指标重选（可辨识性 + 敏感性双体检，2026-11-02）

> 结论先行：A_soft 的 8 个指标里，**3 个是准常数**（`bottom_blank` / `left_blank` /
> `right_blank`，篇内损失极差 0.055–0.073，占原分值的 33%），**1 个是阈值型**
> （`band`，连续分无效但高值端判据仍有效），**4 个该保留但要改口径**
> （`ink_ratio` 需按角色分层；`max_gap` 需改成"页中段空洞"并排除末页自然留白）。
> 另外修正一条我 17:00 前后的口误：`top_blank` 不是二值指示器，扩样后它在 body 页
> 仍有 0.202 的损失极差，**应当保留**。

## 1　两个体检的分工

单看任何一个都会误判，所以做了两套：

| 体检 | 工具 | 回答的问题 | 误判风险 |
|---|---|---|---|
| **可辨识性**（语料侧） | `tools/soft_identifiability.py` | 真实论文里这个指标动不动？动了多少**损失**？ | 会把「只在异常页才动」的指标误判成死数 |
| **敏感性**（评测侧） | `tools/soft_sensitivity.py` | 版面坏掉时它动不动？ | 不知道哪种坏法重要，只知有反应 |

样本：可辨识性 **27 篇 / 512 页**（70 篇取样，43 篇因并行渲染竞态失败——
已修为 uuid 前缀，重跑可补齐）；敏感性 8 个受控变体（每个只改一处版面）。

## 2　可辨识性：篇内损失极差（不是原始值）

判据用**损失**（`w·(1−e^(−d²/2))`）的篇内极差，因为 A_soft 直接吃这个量；
用原始值会被量纲骗（`bottom_blank` 均值 0.06，变化 0.002 也能有 3% 的 CV）。

**主样本 90 篇 / 1502 页**（角色构成：body×1297、dense×91、sparse×99、near-empty×15）：

| 指标 | 篇内损失极差 | 只看 body 页 | 跨篇 CV | 判定 |
|---|---|---|---|---|
| `top_bottom_ratio` | 0.468 | **0.297** | 2.75 | keep（唯一在正文页有连续信号的） |
| `ink_ratio` | 0.322 | 0.039 | 0.25 | stratify（97% 的变异来自页类型） |
| `max_gap` | 0.283 | **0.000** | 0.31 | 不做连续分处理，见下 |
| `top_blank` | 0.199 | 0.099 | 0.30 | 与 `max_gap` 冗余（body 层 ρ=0.837）→ 合并 |
| `right_blank` | 0.130 | 0.011 | 0.28 | 与 `left_blank` 冗余（ρ=0.876） |
| `left_blank` | 0.005 | 0.005 | 0.34 | drop |
| `bottom_blank` | **0.000** | 0.000 | 0.51 | drop（篇内完全没有变异） |
| `band` | — | — | 1.31 | threshold-only |

方法学提醒（要写进论文）：**同一套判据在 27 篇样本上会给出不同结论**
（例如 `top_blank` 当时 0.202 被判 keep，`max_gap` 被判 stratify）。
样本翻 3 倍后数值稳定下来，所以这里以 90 篇为准，并把「样本敏感性」本身
记成该方法的一条局限。

冗余（body 页，|ρ|≥0.8）：

- `left_blank × right_blank = 0.876`
- `max_gap × top_blank = 0.837`

`max_gap` 的正确读法：**它在正文页上完全不动（0.000），因为正常正文页没有大空洞——
这恰恰是它的职责**。若按"篇内变异"判死，就会把唯一能抓"页中大洞"的指标删掉。
所以要看第二套体检。`top_blank` 与它的重叠既然在 body 上都到 0.837，两者留一个即可；
`max_gap` 对坏版面的反应强度是 `top_blank` 的 3.7 倍（见下节），留 `max_gap`。

## 3　敏感性：坏版面下谁有反应

8 个受控变体：baseline / big-gap / sparse / bottom-flush / imbalanced /
full-figure / wide-table / dense-text，各量 8 指标的单页损失。

| 指标 | 变体间损失极差 | 不同取值数 | 判读 |
|---|---|---|---|
| `max_gap` | **1.384** | 8/8 | 最强，抓大洞/稀疏 |
| `ink_ratio` | **0.686** | 7/8 | 强，抓密度异常 |
| `top_bottom_ratio` | **0.526** | 5/8 | 强，抓上下失衡 |
| `right_blank` | 0.399 | 3/8 | 反应来自**双栏**，不是质量 |
| `top_blank` | 0.374 | 3/8 | 抓"内容全挤上面" |
| `bottom_blank` | 0.148 | 2/8 | 弱 |
| `left_blank` | 0.002 | 2/8 | 死 |

`right_blank` 唯一一次强反应出现在 `dense-text`（双栏）变体——它量的是"这页是不是
双栏"，不是"这页排得好不好"。这巩固了 drop 决定。

**顺带暴露一个真问题**：合成 `baseline`（干净正文页）的 `max_gap` 损失就有 0.379，
来源是**末页尾部空白**被当成"页内大洞"（实测 max_gap≈0.294 全在末尾）。
`find_defects` 早就用 `max_gap_at ∈ (0.15, 0.85)` 排除了尾部，但 A_soft 没做。
这是 v2 必须修的口径漏洞。

## 4　SOFT_SPEC v2 草案

综合两套体检，8 个指标收敛成 **3 个连续分 + 1 个阈值型**：

| 指标 | 处置 | 具体改动 |
|---|---|---|
| `max_gap` | **保留 + 改口径** | 只计**页中段**空洞（`0.15 < max_gap_at < 0.85`），末页/页首自然留白不计；这是异常检测的主力 |
| `ink_ratio` | **保留 + 分层** | 只在 `body` / `dense` 页计分；`sparse`（整页图/稀疏页）跳过，避免把「图页密度低」当缺陷 |
| `top_bottom_ratio` | **保留** | 全页计分，口径不变；这是唯一在正文页内部也有连续信号的指标 |
| `top_blank` | **删（并入 max_gap）** | body 层与 `max_gap` 相关 0.837，反应强度只有 1/3.7 |
| `bottom_blank` | **删** | 篇内损失极差 0.000；降级为「压页是否把正文压进版心底」的几何校验 |
| `left_blank` | **删** | 0.005，敏感性 0.002 |
| `right_blank` | **删** | 与 left 冗余 0.876，敏感性反应来自双栏而非质量 |
| `band` | **保持 w=0** | 阈值型：`band ≥ 0.40` 仍是 `giant_content` 判据，走门控/报告 |

权重过渡值（等第 3 步 BT 标定后替换）：保留 3 项现权重和 = 3.4，
原总和 5.5 → ×1.618 让 A 的绝对量级不变：
`max_gap` 2.27 / `ink_ratio` 1.62 / `top_bottom_ratio` 1.62。
**这不是新判断，只是换算**；真正的相对权重等人工成对比较作答后再定。

需要说明的风险：指标从 8 个减到 3 个，A_soft 的表达能力下降，但换来的是
「每个留在里面的指标都能被证明有信号」。若后续发现漏检（例如某类版面问题
没人抓），应该**新增有证据的指标**，而不是把死数塞回来。

## 5　角色代理（已实现）

`texopt/visual.py: pixel_role()` —— 闭环里不可能每轮跑 pdfminer，所以用像素量粗分：

```
near-empty   ink ≤ 0.02
sparse       ink < 0.55 × 本篇页墨迹中位数      （整页图/大留白）
dense        ink > 1.60 × 本篇页墨迹中位数      （图表/公式密集）
body         其余          + first-page / last-page 标记
```

`role_source="pixel-proxy"` 明确标注这是近似，不冒充 `roles.py` 的语义角色。
实测 512 页构成为 body×424、dense×44、sparse×38、near-empty×6——
说明这层代理确实把页类型分开了。逐页诊断（`page_score`）现在会标注每页角色。

顺带修掉一个并发 bug：`visual._render` 的 PGM 前缀原来固定为 `gray`，写到 PDF 所在
目录，多线程跑同一目录会互相覆盖（本次体检 43 篇失败就是这个）。现在默认前缀带
pid + uuid。
