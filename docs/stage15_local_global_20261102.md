> 结论先行：这一阶段做了两件事。
> **① 修掉连档压页的机制 bug**（gate 定向修复里，单步不减页就回滚，导致「连收两档

> P 与 model2 的 A_soft 都拆成「能归到页」和「归不到页」两部分，并同时给出

> **打分口径没有任何改动**：ρ=15、14 项 c\*、M1/M2 的公式与聚合全部原样——所以
> 阶段 13/14 的标定继续有效。

## 1　连档压页：机制 bug

### 1.1 现象

TeX 断页是**台阶式**的：收一档边距常常一页不减，要连收两三档才兑现。旧逻辑
（阶段 12 起）在 gate 定向修复里要求**每个单步**都严格减页：

```python
same_but_fewer_pages = (违规数相同 and nper.pages < per.pages)   # 旧判定
if fewer or same_but_fewer_pages: 接受
else: 回滚 + 永久 blocked
```

于是第一档（25mm→23mm，仍 2 页）被回滚并记入 `_blocked`，第二档根本没机会执行。
结果是**「多档才减页」这一类修复永远不可能发生**，只能靠「单步刚好跨过断点」的运气。

### 1.2 修法：暂存链（provisional chain）

```
每一步试算后分三类：
  兑现（违规减少 / 页数减少） → 本步 + 之前所有暂存档一起提交
  暂存（违规不增、页数不增） → 保留状态继续往下压，记入链
  变差（违规变多 / 页数变多） → 回滚
暂存链长到 gate_repair_plateau（默认 3）仍未兑现 → 整链回滚到链首 + blocked 最后一步
```

两个新字段（`texopt/requirements.py`）：`gate_repair_rounds=12`（原有语义，补上声明）、
`gate_repair_plateau=3`。

关键设计：**暂存不是接受**。整链兑现才真的留下改动；兑现不了就全部撤销，
所以不会把「收了三档边距、一页没省」的累计破坏留在稿子里。

### 1.3 验证（`s14/plateau-*`，9 项）

靶稿不是拍脑袋造的，是实测标定出来的：8 段 × 6 句 lorem，a4/10pt，
边距 25mm→2 页、23mm→2 页、21mm→1 页。

| 测试 | 结果 |
|---|---|
| `plateau_off`（把上限设成 1，等于旧行为） | BLOCKED_GATE ✅（证明旧逻辑确实做不到） |
| `plateau_on`（默认 3） | 压进 1 页，最终边距 ≤21mm ✅ |
| `plateau_rollback`（9 段，怎么收都不减页） | BLOCKED_GATE 且边距回到 25mm ✅ |

最后一条是**整链回滚**的证据：不允许把没兑现的改动留在稿子里。

## 2　单页打分：为什么需要，怎么加

### 2.1 问题

| 层 | 现状 | 后果 |
|---|---|---|
| model1 · P | 全文**按次数线性求和**，没有「最差页」概念 | 一页 20 处溢出 ≈ 20 页各 1 处；局部烂页被摊平 |
| model2 · A_soft | 已有局部/整体聚合（0.5·最差 k 页 + 0.5·页均） | 两条线口径不一致 |
| 报告 | 只有全篇 P / A | 看不出「哪一页最差、差在哪」 |

### 2.2 归因：日志缺陷怎么落到页上

日志里的 overfull/underfull 只给**源码行号**，不给页号。解法：编译时加 `-synctex=1`，
用 `synctex view -i line:1:file -o pdf` 查页号（`engine.synctex_pages`，带缓存）。

| 缺陷 | 归因方式 |
|---|---|
| overfull / underfull / 表格超宽 | 源码行号 → SyncTeX → 页号 |
| 源码卫生项（22 类） | 同上（扫描时带行号） |
| 浮动体 `[H]` 强排 / 参数不稳定 | 浮动体所在行 → SyncTeX → 页号 |
| 渲染层视觉缺陷（内容孤立、近空白页） | 本来就有页号 |
| vbox 垂直质量、浮动体警告、其余 Warning、质量宏缺失、超宽图表达式 | **归不到页**（日志无行号 / 属文档级），单列 |

### 2.3 三种读法（同一份数据，不替人做选择）

```
mean = 全篇页均            → 整体水平
topk = 最差 k 页的均值      → 局部病灶，k = max(1, round(5%·页数))
peak = 单页最差            → 最坏情况
```

实测（examples/issues.tex 原件，3 页）：

| 口径 | model1 · P | model2 · A_soft |
|---|---|---|
| 页均 | 1.311 | 1.769 |
| 最差 1 页 | 1.900 | 2.618 |
| 单页峰值 | 1.900 | 2.618 |
| 全篇 | 5.933（含 2.0 归不到页） | 1.232（文档级聚合） |

第 3 页 `near_empty`（0.6）+ A_soft 2.618 是全篇最差的一页，但它在全篇 P 里只占 10%。
这就是「整体分把局部掩盖掉」的具体例子。

### 2.4 边界：这一层**不改判定**

- `total_score` 不变（M1 = ρ·P + I，M2 = A_soft），ρ=15 与 14 项 c\* 继续有效；
- 只在 `finalize()` 里算一次诊断，写进 `state.json.page_diagnostics` 和
  `report.md` 的「逐页诊断」小节；失败时不影响主流程；
- 不做逐页闭环优化：动作面大多是**全局**的（边距、字号、浮动体参数），
  以单页分为目标会诱导「修好这页、害了别页」。

## 3　还没定的三件事（需要拍口径，才敢动公式）

1. **P 要不要加局部项**：`M1 = ρ·P + ρ_peak·P_peak + I`？好处是最差页不会被平均掉；
   代价是要重新标定 ρ_peak（问人 2–3 题：一页烂 vs 两页中等），且 M1 量纲变了，
   阶段 13/14 的数要重跑。
2. **同类缺陷要不要饱和**：现在同页 20 处 overfull 线性累加。可改 `n0·n/(n0+n)`，
   同样会改量纲 → 需要重标。
3. **局部恶化要不要否决全局改善**：现在是「全局 M1 严格改善就接受」，所以
   「整体略好、但某一页明显变差」会被放行。若要拦，需要阈值 θ 的口径与优先级。

在这三件事拍定之前，本阶段的定位是**把局部/整体的账记清楚**，而不是改分数。
