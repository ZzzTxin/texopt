一句话总结：这套评分只用两个公式。model1 判断一份稿子「能不能用、改了多少」—— 不能用的直接淘汰，能用的比较「改动代价」；model2 给「好不好看」打分。 最终排序：先看能不能用（L），再看改动多少（I），最后看好不好看（A）。

1. 两个公式分别在回答什么问题

公式回答的问题输入作用
model1
L + I		 这份稿子能不能用？为了得到它，我动了多少？ 重编译后的整篇文档（页数、编译结果、源码规范）+ 原稿 否决权：L > 0 直接淘汰；L = 0 的稿子之间比 I（越小越好）
model2
A		 这份稿子排得好看吗？ 编译日志里的缺陷 + 渲染出的页面图像 + 同档语料的统计常态 打分权：只在都可行、改动代价相近时用来分优劣
为什么必须分开？因为两件事的「可比性」不同。 「能不能用」是不可协商的（编译失败就是不能用），而「好不好看」是偏好性的（可以慢慢调）。 混在一个公式里，要么必须用超大权重把硬约束顶上去（旧实现里那个 10⁶）， 要么就很难解释「为什么这份稿子赢了」。

判定顺序（当前实现 vs 设计目标）

现在代码里是一个标量总分（越低越好）：

{{EQ:eq_total_now}}

也就是：硬约束违规数量 × 10⁶ + 审美分 + 改动代价。10⁶ 之所以这么大，就是为了保证 「只要 L 不为 0，无论 A 多好看都会被淘汰」。

设计上更干净、也更容易写进论文的写法是字典序：先比 L，再比 I，最后比 A。 两者在本项目的搜索场景里结论一致（因为 10⁶ 远大于 A、I 的取值范围）， 把总分改成字典序属于可选重构，不是必须。

一个关键约定：所有量都建立在 R(x′) 上，也就是「先整篇重编译，再全局重评」。 不存在「对某个段落单独打分再拼起来」。这就是项目一直在强调的 「局部最优 ≠ 全局最优」——压好了某一页，可能导致后面几页全乱。

3. model1 逐项讲解

3.1 硬约束 L：只有 4 类，全是 0/1

{{EQ:eq_L}}

读法：把「不能碰坏的 4 类东西」各自转成 0 或 1，乘以自己的权重，加起来。 每项只有 0 和 1 两种取值，没有中间态。

项什么时候是 1公式为什么不可协商
ℓ_compile
编译渲染		 编译失败，或没产出 PDF {{EQ:eq_lcompile}} 编译不过 = 这份稿子没有任何交付价值
ℓ_page
页数		 有页数要求且超出 {{EQ:eq_lpage}} 会议/期刊的页数上限是投稿门槛，没有商量的余地
ℓ_spec
硬性规范		 要求里点名了的规范项不符（字号 / 页边距 / 公式居中 / 目录 / 页眉） {{EQ:eq_lspec}} 要求「明确写了」的才算；没写的一律尊重原稿，不拿它扣分
ℓ_fig
图表保真		 图/表的指纹（内容+环境）与原稿不一致 {{EQ:eq_lfig}} 排版工具不该「重画」用户的图
为什么坚持 0/1：这是你的口径要求——页数上限属于「门槛」，不是「分数」。 超过 0.2 页和超过 5 页在 L 里完全等价，都判不可行。 代价是这个维度上没有梯度（见 3.5 的处理办法）。

3.2 页数：有要求时才是变量，没要求时变量根本不存在

这一点很容易被忽略：b = ∅ 时，不是「ℓ_page = 0」，而是这一项 不出现在求和里（数学上叫「该维度不存在」）。代码里就是一层 if req.page_limit: 的门。

要求里有页数吗ℓ_page 是否存在取值后果
b = 12，稿子 11 页存在0可行
b = 12，稿子 12.5 页存在1不可行（超一点也是超）
b = 12，稿子 30 页存在1不可行（与上一种情形同权）
没写页数要求不存在—页数完全不参与评分

3.3 正文内容保留：为什么被「降级」，以及怎么量化

为什么降级：项目后续要加入「语义抛光」——为了排版可能需要改写句子。 如果内容完整保留还挂在硬约束里，那么任何一句改写都会让候选稿直接不可行，语义抛光就永远无法执行。 所以它被移到代价侧：可以改，但要付出代价。

{{EQ:eq_dcontent}}
{{EQ:eq_keep}}

其中 n_c(·) 是字符 c 在「内容面文本」中出现的次数。 「内容面文本」= 抽正文 → 抹掉排版命令可动面（浮动体参数、图宽、\newpage、\noindent 等） → 空白折叠。也就是只统计真正的文字内容。

手算例子（原句：We study the lazy dog.）

候选稿正文为什么D_content
We study the lazy dog.完全没动0.00
We study the cat.替换了一个词（lazy dog → cat）0.40
We study the lazy dog. It is fast.加了一句0.33
 （正文被清空）正文全没了1.00
\noindent We study the lazy dog.只加了排版命令0.00
We study the lazy dog .只差空格0.00

数值由当前实现实算得出（字符多重集 Jaccard：Keep = Σmin/Σmax，D = 1 − Keep）。

诚实边界：D_content 是改动幅度代理，不是语义等价证明。 它按字符重合率算，所以「同义改写」（把 fast 改成 quick）会被算成偏差。 这是有意保守：宁可多报，也不漏报。 语义抛光阶段还会再加一道硬底线 Keep ≥ κ。

3.4 干预代价 I：改得越狠越贵

{{EQ:eq_Istruct}}
{{EQ:eq_I}}
项含义系数例子
|Δm|页边距相对原稿的偏移（mm）0.5 / mm25mm → 20mm：+2.5
|Δf|正文字号降档数3.0 / 档11pt → 10pt：+3.0
N_float浮动体位置参数被改的处数0.4 / 处2 处 [h]→[tbp]：+0.8
N_width图片宽度表达式被改的处数0.4 / 处1 处 170mm→\linewidth：+0.4
β·D_content正文改动幅度β = 50改了一个词（D=0.40）：+20.0

上面前四项合起来就是代码里的 intervention_cost()，记作 I_struct； 内容项由 CONTENT_PENALTY × D_content 单独相加。两者之和才是完整的 I。

为什么要这样设计：因为「松弛方向天然便宜」。 比如为了压页把边距压到 15mm，发现其实 18mm 也够——那么从 15mm 改回 18mm 会让 |Δm| 从 10 降到 7，I 自动下降。于是系统在达标之后会自己把参数收回临界点： 既满足要求，又离原稿最近。

3.5 一份候选稿是怎么被判定的

  1. 整篇重编译 → 得到 R(x′)。
  2. 算 L：4 类硬约束逐项 0/1 相加。L > 0 就淘汰（等价于 J₁ = +∞）。
  3. L = 0 的稿子算 I_struct、D_content、A。
  4. 比较：认定总分 = 10⁶·|L| + A + I；设计目标是字典序 (L, I, A)。
{{EQ:eq_J1}}

必须写进论文的取舍：页数改成 0/1 之后，L 在「页数」这个维度上不提供梯度—— 超 1 页和超 5 页同分。所以搜索阶段会另用一个启发量 g = max(0, 页数 − b)，只用来挑动作方向、排序候选， 并作为提示输出（「离达标还差 0.3 页」）。g 绝不进入 L，也绝不参与最终验收。

3.6 常见误解（FAQ）

Q1：为什么不用一个公式把 L、I、A 一起加起来？
可以，但那样必须给 L 极大的权重，否则「好看但编译失败」的稿子可能胜出。 那正是旧实现里 10⁶ 的来历。分开写能让每件事的标准都说得清楚， 也方便后续只改其中一个（比如只调 A 的权重）。
Q2：内容保留都拿掉了，会不会把用户正文删光？
不会。它只是不再「一票否决」，仍然是代价项且 β = 50（一次改词的代价约等于压 5 档字号 + 40mm 边距）。 另外语义抛光阶段还有硬底线 Keep ≥ κ。真正需要担心的不是「被删光」， 而是「同义改写被算成偏差」——这是刻意保守的方向。
Q3：页数 0/1 之后，搜索会不会变成瞎走？
不会。搜索方向用启发量 g = max(0, 页数 − b)（它是连续的，只在挑动作时使用）， 验收用严格的 L = 0。两者职责分离：g 负责「往哪走」，L 负责「算不算达标」。
Q4：为什么「超 0.2 页」不判得比「超 5 页」轻一点？
因为上限不是打分项而是门槛（投稿系统不接受 12.5 页）。要体现「快到了」的进度感， 就用 g 做提示，而不是把它写进 L。
Q5：model1 的 I 和 model2 的 A 谁先谁后？
设计目标是先 I 后 A（同样可行的稿子，尽量少动；动一样多时，再挑好看的）。 当前实现是相加，两者在数值上量级不同，所以严格来说这是个已知的口径待统一项。
Q6：现在代码里还有 10⁶ 吗？
还在（L_PENALTY = 1e6）。它和 J₁ = +∞ 语义等价，只是「手写版」。 换成可行性门 + 字典序是一个独立的小重构，可以做，但不影响现在的正确性。

4.1 总式

{{EQ:eq_A}}

读法：审美分由两部分组成。第一部分 A_defect 来自「看得见的毛病」（编译日志 + 渲染出来的页面图像）， 现在就在生效；第二部分 A_profile 来自「和同类论文的常态比，偏得远不远」， 目前处在影子模式（λ = 0，只报告、不改分）。

4.3 A_profile：和「同类论文的常态」比，偏得远不远

用体检类比：A_defect 像是在查「有没有明显的病」，A_profile 是在查 「各项指标是不是偏离了同龄人的正常范围」。

第一步：先分档。不能拿「会议论文的摘要页」和「学位论文的附录页」互相比较。 所以按 (会议, 页面角色, 栏数) 分成一个个「档」，每个档有一套自己的正常范围 （中位数 m、IQR s、上下界 lo/hi、相关系数阵 R、归一化基准 ref）。

第 1 步：重尾变换

{{EQ:eq_s1}}

为什么：像「图占正文面积比」这类指标是重尾的（少数论文特别高）， 取对数后分布才接近正态，后面的统计量才有意义。只对正比率类维度做。

第 2 步：标准化

{{EQ:eq_s2}}

z 表示「偏离本档中位数几个 IQR」。裁剪到 ±4 是为了不让单个离群页主导全局。

第 3 步：带外损失（双向、非单调）

{{EQ:eq_s3}}

太低和太高都要扣分，不是越大越好也不是越小越好。 权重不对称（W_low > W_high）：版面偏空通常比偏满更刺眼，所以「低于下界」罚得更重。

第 4 步：归一化到可比较的尺度

{{EQ:eq_s4}}

除以该档自己的 P90（ref），并封顶 20，避免某一个维度因量纲不同而吃掉全部权重。

第 5 步：马氏距离（整体偏离）

{{EQ:eq_s5}}

直观理解：不只看每个维度偏了多少，还看「这些偏离方向组合起来是否罕见」—— 如果两个维度在正常论文里总是同增同减，那它们同时偏高就不算异常（相关系数阵 R 负责这件事）。 Σ 用 Ledoit–Wolf 收缩（δ 由数据解析求得），是为了在小样本下也能把协方差阵估稳。

第 6 步：页 → 文档聚合（CVaR 式）

{{EQ:eq_s6}}

为什么不用最大值：一个离群页会把整篇拖死。为什么不用平均值：整整一页的明显退化会被稀释。 所以取「前 5% 大页的均值」和「全体均值」各占一半——既对局部异常敏感，又不被单页主导。

第 7 步：合成

{{EQ:eq_s7}}

各维度加权平均（权重由阶段 7 的标定流程给出；未标定时全部取 1，即等权）， 再加上马氏距离项（w_M = 1）。

4.4 λ = 0 的影子模式

A_profile 目前不参与打分，只写进报告供人工核对。 原因：它的权重还没通过标定门槛。代码里 assert_lambda_allowed() 会在 λ ≠ 0 且标定未通过时直接报错——这是刻意的「不许偷偷启用」。 后续要通过「成对比较 + Bradley–Terry 拟合」得到可解释的权重，才允许把 λ 打开。

4.5 诚实边界（写进文档时必须带上）

  • A_profile 是排序量，不是「人类审美评分」；它只覆盖「与常态的偏离」这一层。
  • A_defect 看源码 + 渲染，A_profile 只看渲染，两者测的不是同一件事，只能相加、不能互相替代。
  • 人主观偏好的那一层（例如「我更喜欢留白多一点」）目前没有建模。

7. 术语表

硬约束 / 可行性
编译、页数（有要求时）、明确点名的规范、图表保真这四类。L = 0 才叫可行。
干预代价
为了让稿子达标而对原稿做了多少改动，越小越好。
审美代理
用可计算的统计量近似「好看程度」，不声称等于人类审美判断。
档案（profile）
按 (会议, 页面角色, 栏数) 分组后，从大量语料统计出的「正常范围」。
影子模式
新指标只计算、只报告，不参与验收/打分，用来先积累证据。
CVaR 式聚合
取「最差的那一小部分」的平均，兼顾敏感性与稳健性。
字典序
先比第一个指标，相同再比第二个：像查字典一样，而不是简单相加。
内容面文本
抽掉排版命令、折叠空白之后的正文，用来衡量内容改动幅度。
