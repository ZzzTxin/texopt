texopt 模型 v3 结构设计说明

2026-10-14 · 依据你「model1 不应作为量化公式 / model2 只做审美」的修改意见重写 · 配套：model_v2_explained_20261014.html（记号与逐项讲解仍可复用）· model_v2_formulas_20261014.pdf

一句话：把原来的「L 硬约束公式 + A 审美公式」拆成三层 —— 底层逻辑门（必须满足，不评分）、model1（页面缺陷 + 修改情况，主目标）、 model2（纯审美软指标 + 与同类论文比较）。

1. 三层结构与职责

层回答什么数学形态是否参与打分
底层逻辑 Gate 这份稿子算不算可用 条件集合，每项 0/1；不是公式 否。不满足即不可行（+∞ / 直接淘汰）
model1 页面缺陷有多少？为了改它我动了多少？ M₁ = ρ·P + I（一个式子综合衡量） 是，主目标
model2 排得好看吗？（灰度 / 留白 / 占比 / 均衡 + 与同类论文比） M₂ = A_soft + λ·A_profile 是，次目标（λ 默认 0 → 语料比较部分仅报告）

Gate 的实现形式是「违规清单」（代码 gate_violations()）： 清单为空 = 可行。之所以返回清单而不是布尔，是为了让报告说清楚「卡在哪一条」， 也为了让验收判断能用「违规条数」先做一级比较。

2. model1：页面缺陷 + 修改情况

2.1 P：页面缺陷分（半硬性约束，按比重累加）

项比重说明
overfull 行溢出1.0正文右侧超出版心
underfull 行欠满0.6字间距被拉稀，常批量出现
vbox_over 页盒溢出1.0页面垂直方向被撑破
vbox_under 页盒欠满1.4孤行寡行的 TeX 侧代理，与断页质量同源
floatwarn 浮动体警告1.6浮动体错位：位置/尺寸被 TeX 强改

fig_overwide 图片超宽1.0有缩图修复动作

2.2 I：整体修改情况（越小越好）

I_struct 是结构改动代价：页边距每 mm 计 0.5、字号每档 3.0、浮动体参数每处 0.4、图宽每处 0.4。 β·D_content 是正文改动代价（β = 50），D_content 见上式（内容面字符多重集 Jaccard 的补）。 「松弛方向天然便宜」依然成立：达标后把参数往回收会自动降 I。

2.3 ρ 的语义：两种量怎么换算

ρ = 2.0 是一个「秤定汇率」，读法是： 消除 1 个加权缺陷（例如 1 处行溢出），我们愿意付出 2 个代价单位 ≈ 4mm 页边距改动 ≈ 5 处浮动体参数改动。
ρ 大 → 更愿意改版面去消灭缺陷（苛刻）；ρ 小 → 更保守（宁留缺陷也不动原稿）。 这是需要标定的一个数，不是自然常数；建议后续用「人工成对比较」来定（阶段 7 的 Bradley–Terry 流程可直接用）。

3. model2：纯审美量化

3.1 A_soft：绝对软指标（带理想区间的带外损失）

软指标 x_i理想带 (lo, hi)权重对应你的关注点
ink_ratio 页墨迹占比(0.020, 0.150)1.0页面灰度（整体浓淡）
bottom_blank 页底留白(0.000, 0.220)1.5留白情况
top_blank 页首留白(0.000, 0.120)0.6留白情况
max_gap 页内连续空洞(0.000, 0.150)1.2留白情况
band 最大整块内容占页高(0.050, 0.350)3.0图表占比（整页单块过大）
left_blank / right_blank(0.000, 0.180)0.6 / 0.6版心左右留白
top_bottom_ratio 上下半页墨迹比(0.700, 1.400)0.8均衡（上重下轻）

鲁棒性：单页单指标损失封顶 3.0，比例类指标做 clip（例如 top_bottom_ratio 裁到 5.0）， 避免「下半页几乎空白 ⇒ 比值爆到几百」这种极端值主导全局。

3.2 A_profile：与同类论文比较（λ 默认 0，只报告）

这一部分沿用原有七步（重尾变换 → 标准化 → 带外损失 → 归一化 → 马氏距离 → CVaR 聚合 → 加权合成）， 参考系不是先验带，而是同会议 × 同页面角色 × 同栏数的语料档案。你这次没提意见，我保持原样不动， 公式见速查卡与 docs/stage4_aesthetic_profile.md。

4. 排序与验收

  1. gate 优先：违规条数少者胜（少一条就赢，不比其它）。
  2. 压页阶段例外：双方都还超页数时，页数不增即保留（省页常需连续多档才兑现）。
  3. model1 改善即接受：M₁ 严格变小就接受（缺陷与代价已按 ρ 换算，不再需要旧版「A 优先」特例）。
  4. M₁ 持平：model2 改善才接受。
  5. M₁ 小幅变差但总目标 M₁+M₂ 改善：接受（审美收益补偿缺陷/代价回退）。
  6. 否则拒绝并回滚。

6. 我已落地 vs 待你确认

已落地（代码 + 测试）

  • score.py：gate_violations()（旧 l_violations 保留为别名）、 page_defect_score()（P）、aesthetic_score()（改为 model2 的 A_soft）、 total_score() 返回 gate/P/I/M1/A/M2/total。
  • core.py：验收改为 §4 的六条；日志与报告同步显示 gate / P / I / M1 / M2。
  • 权重表集中在 score.py 顶部（W_PAGE_DEFECT、PAGE_DEFECT_WEIGHT、 VISUAL_DEFECT_M1、SOFT_BANDS、SOFT_LOSS_CAP、CONTENT_PENALTY），改一个数就能调。
需要你拍板的四件事：
  1. ρ = 2.0 是否接受作为默认汇率？它直接决定「为消灭一个缺陷愿意改多少版面」。 现在取 2.0 是折中值；你若觉得应当更激进（更愿意动版面），就调大到 3–4。
  2. 源码卫生问题是否属于 model1？我倾向于是（它们是有对应修复动作的具体缺陷）， 但它们确实不是「页面」上的东西 —— 若你认为它们该独立成第三类，我照改。
  3. 「内容孤立 / 几乎空白页」我放在了 model1（放置错误）， 而「页底大片留白」放在 model2。两者的边界由我拍的，可能需要你确认口径。
  4. 一个实测变化：靶稿 chaotic_layout 的出口状态从 DONE 变成了 NEEDS_REVIEW —— 因为「缩小满宽图」这次被新权重判为净负收益（M₁ +1.8 代价 > M₂ 收益）， 于是留下一项 high 的 giant_content（图表占比类，已按新口径归 model2）。 要么接受现状（如实报 NEEDS_REVIEW），要么调大 band 权重 / 调小图宽改动代价， 让这条修复重新划算。这条我需要你选。
