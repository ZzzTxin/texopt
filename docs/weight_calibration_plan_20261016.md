# 评分模型改进方向：把「拍出来的比重」换成「有依据的比重」

> 2026-10-16 · 针对 v3 结构里 model1 · P 的 12 个缺陷比重（`PAGE_DEFECT_WEIGHT`）
> 以及 model2 · A_soft 的部分权重，提出可执行的标定与改造方案。
> 一句话：**频率当分母（从语料来），严重度当分子（从人和数据来），形式先改对。**

---

## 0. 一句话结论

现在 P 里的 12 个比重**没有任何数据来源**，是 9 月最初实现时手工设定的定性判断，
v3 只是把数字原样搬进了字典。改进方向是把每个比重拆成两个可解释的部分：

```
wᵢ  =  严重度ᵢ  ÷  频率ᵢ
        ↑             ↑
     人 + 语料      语料（目标会议的容忍度）
```

并在动权重之前，先修掉两个更严重的问题：**线性计数假设**（D2）与
**gate 内部无优先级**（D5）。

### 1.1　D1　12 个比重没有任何来源

**是什么**：`PAGE_DEFECT_WEIGHT` 里的 12 个数（overfull 1.0 / underfull 0.6 /
vbox_under 1.4 / floatwarn 1.6 / …）全是定性判断，一路从 9 月的最初实现带下来，
v3 只是把它们原样搬进字典，数值一个没动。`HYGIENE_WEIGHT`（源码卫生比重）
注释里写明是"按能否被确定性动作修复 × 影响程度定"——纯主观排序。

**后果**：别人问"凭什么是 1.6 而不是 1.2"，没有答案。

**怎么改**：见第 2、3 节（拆成严重度 ÷ 频率）。

---



### 1.2　D2　线性计数假设（最严重，属形式错误）

**是什么**：缺陷分是"有多少处就乘多少"，一路加到底，既不减速也不封顶。

**代码**：`texopt/score.py` → `page_defect_score()`

```python
p = (w["overfull"]  * len(iss["overfull"])
     + w["underfull"] * len(iss["underfull"])
     + w["floatwarn"] * len(iss["floats"])
     + ...)                      # 每一类都是 权重 × 条数，直接相加
```

**具体例子**：一篇 80 条 underfull（欠满）的稿子 vs 一篇只有 1 处表格超宽的稿子：

- 前者：80 × 0.6 = **48 分**
- 后者：1 × 1.2 = **1.2 分**

表格超宽被彻底淹没。但这里有两个问题：

1. **"80 条"往往是同一个原因造成的**：一个段落断行坏掉可能连着产生十几条欠满，
  等于同一个毛病被数了很多次，属**重复计账**。
2. **人眼不是这么看的**：第 1 条欠满看得出来，第 80 条已经感觉不到——
  感知早已饱和，可分数还在线性上涨。

**后果**：靠数量取胜的类别（欠满、警告）压死其余类别；分数与人眼感知脱钩。
**这是为什么它比"权重没依据"更严重**——哪怕 12 个权重标定得完美，
只要还按"数量直接相加"算，问题依旧。

**怎么改**：给每类加**饱和曲线**：`p = Σ wᵢ·g(nᵢ)`，前几处按原权重计，
之后递减、趋向封顶。这样"有没有这个毛病"比"有多少条"更重要。
饱和尺度 `τᵢ`（多快开始饱和）可由语料的计数分布定（如取 P50/P90）——**这部分可数据化**。

### 1.3　D3　model2 的维度权重与不对称系数仍手拍

**是什么**：审美那半边每个指标一组数 `(理想下限, 理想上限, 这一维的权重)`。

**代码**：`texopt/score.py:63`

```python
SOFT_BANDS = {
    "ink_ratio":        (0.020, 0.150, 1.0),   # 灰度/墨迹密度
    "bottom_blank":     (0.000, 0.220, 1.5),   # 页底留白
    "band":             (0.050, 0.350, 3.0),   # 图表块占页高
    "top_bottom_ratio": (0.700, 1.400, 0.8),   # 上下均衡
    ...
}
W_SOFT_LOW, W_SOFT_HIGH = 1.2, 1.0   # 偏空 vs 偏满，哪个罚得重
```

**分三层看，只有第一层做了一半：**

1. **理想区间的两个端点**：这层拿语料校准过（例如图表页覆盖率 0.50 → 0.36，
  取自语料 P95；正文覆盖率上限 0.25 → 0.30，取自语料 P25）。**这层有依据。**
2. **每一维的权重**（1.0 / 1.5 / 0.6 / **3.0** / 0.8 …）：**手拍**。
  特别点名 `band` = **3.0**：图表块占比这一维权重最高，是"页底留白"(1.5) 的两倍、
   "页首留白"(0.6) 的五倍，没有任何依据。
3. **"偏空更罚"的不对称系数**（1.2 vs 1.0）：**手拍**。

**具体例子（这个已经影响了实际结果）**：正因为 `band` 给了 3.0，
靶稿 `chaotic_layout` 的出口状态从 DONE 变成 NEEDS_REVIEW——
"缩小那张满宽大图"这笔修复，算下来"动图宽"的代价 +1.8 大于 `band` 带来的审美收益，
被判净负收益，于是系统选择**不动**。一个手拍的 3.0 **直接改变了系统决策**。

**怎么改**：并入第 2、3 节的标定（频率当分母、严重度当分子）；
"偏空 vs 偏满哪个更糟"用成对比较直接问人（两张只差留白多少的页图二选一）。

### 1.4　D4　尺度不可辨识（概念问题，但要讲清楚）

**是什么**：进决策的从来不是 `w` 本身，而是 `ρ × w`。所以 `w` 的**绝对值**没有意义，
只有**比值**有意义。

**代码**：`texopt/score.py:35` `W_PAGE_DEFECT = 2.0`（即 ρ），它乘在 P 上：
`M1 = ρ × P + I`

**两个类比：**

- **考试分数**：我说"我考了 85 分"——这分数好坏取决于满分是 100 还是 150。
`w` 是那个"85"，`ρ` 是"满分"。
- **秤**：`ρ` 是刻度（1 格代表多重），`w` 是砝码数量，读数 = 刻度 × 数量。
把刻度调小一半、砝码全部翻倍，读数一模一样。

**具体例子**：


|             | 写法一 | 写法二 | 结果            |
| ----------- | --- | --- | ------------- |
| ρ           | 2.0 | 1.0 |               |
| w_overfull  | 1.0 | 2.0 | 生效值都是 **2.0** |
| w_floatwarn | 1.6 | 3.2 | 生效值都是 **3.2** |


两套设定**完全等价**，系统行为一个字都不会变。

**后果**：

1. "这 12 个权重的绝对值该取多少"这个问题**数学上没有答案**，写多少都行。
2. 论文里写"权重 1.6 是标定结果"会被问倒——正确的主张是
  **"只有比值有意义，整体缩放不影响任何决策"**。
3. ρ 与权重**绑在一起，必须一起标定**，不能先定权重再定 ρ。

**怎么改**：在文档中明确锚定规则——**权重只定义相对尺度，锚定** `w_overfull = 1.0`**，
绝对尺度由汇率 ρ 吸收**；标定只输出比值 + ρ（各带置信区间）。
实验设计上也因此**不能**让人直接回答"权重是多少"，只能让人回答
"A/B 哪个更糟"（给比值）或"允许改多少毫米边距来换掉它"（给 ρ）。

### 1.5　D5　gate 内部四条等权，无优先级　【已定：方案 B】

**先说清楚不是问题的地方**：gate 作为**前置条件**、必须满足它才有资格谈 M1/M2，
这个逻辑是对的，代码也是这么实现的。

**D5 问的是另一件事**：**在 gate 内部，那四条要不要排优先级？**
现在的实现是不排，只看**条数**：

```python
# core.py::Optimizer._accept
if len(n_lv) < len(c_lv): return True,  "底层逻辑（gate）违规减少"
if len(n_lv) > len(c_lv): return False, "底层逻辑（gate）违规增加"
```

条数相同就直接掉到 M1/M2 去比，**gate 四条之间谁更致命完全不看**。

**情形 1：条数相同、性质不同。**

- 候选稿：**超 1 页**（1 条）
- 当前稿：**缺页眉**（1 条）

系统判"条数相同"，转头只看 M1/M2——完全没考虑"超页对投稿是 desk reject 级、
缺页眉只是不合规"。这是它选不出正确优先级的场景。

**情形 2：代码里已经有两个特例在打补丁（最有力的证据）。**

1. **编译失败不走条数比较**：`core.py` 里 `nper.ok` 为假就直接判"不接受，编译失败"，
  根本不进 `_accept`。等于下意识承认"编译失败比别的 gate 违规更致命"，
   但没用权重表达，而是用一句 if 特判掉。
2. **压页阶段特判**：`_accept` 里专门有一段——双方都还在超页数时，
  "页数不增即保留"。翻译过来就是"**页数这一类 gate 违规比其他 gate 违规更需要优先推进**"。
   又是在绕过等权。

**结论**：gate 当门是对的，但门内四条被当成完全平权，导致真正需要优先级的地方
只能靠临时补丁，且说不清"系统到底更在乎哪条"。

**改法（已定：方案 B．分层）**

- **终止级**：编译失败 / 未产出 PDF / 图表被改写 → 直接判死，与其它不可比
- **可修级**：页数超限 / 字号 / 边距 / fleqn / 目录 / 页眉 → 同级之间比条数，级间有明确优先级

好处：① 上述两个特例可以删掉，逻辑收敛成一条规则；② 报告能一眼看出"卡在哪一级"；
③ 以后加 gate 规则有地方放。**不需要任何数据，是纯设计决定。**

### 1.6　D6　权重写死在代码里

**是什么**：所有数字都是 Python 源码常量（`score.py` 第 29–107 行），调一个数就得改代码。

**后果**：

1. **没法带版本号**：报告里看不出"这份结果用的是哪版权重"。
  A_profile 那边其实已有 `weights_version` 机制（`weights.py`），
   说明问题已被意识到，但 P 这边没接上，两边不一致。
2. **没法回滚/对照**：比较"新权重 vs 旧权重"只能靠 git 来回切代码。
3. **别人没法参与**：做人工标定的人要改的是代码，不是配置文件，门槛不对。
4. **论文没法引用**："权重见表"，但表不在代码之外的任何地方存着。

**怎么改**：把 `PAGE_DEFECT_WEIGHT` / `SOFT_BANDS` / `HYGIENE_WEIGHT` /
`VISUAL_DEFECT_M1` / ρ / β 全部挪到 JSON 权重文件（如 `weights/score_weights_v1.json`），
代码只保留默认值兜底；加载时把版本号写进报告与 `state.json`。

## 2. 改进总思路



### 2.1 分母：频率 = 目标会议的「容忍度」

语料里的 608 篇是**已录用**论文。因此：

- 某类缺陷在录用稿里**罕见** → 社区不容忍它 → 权重应**高**
- 某类缺陷在录用稿里**普遍** → 社区接受它 → 权重应**低**

这条推理的科学性在于：对一个"帮助投中目标会议"的工具来说，
"目标会议接受什么样的稿子"就是最直接的身份 ground truth。
必须按 `venue × 角色 × 栏数` 分组统计（沿用阶段 2 档案的分层口径），
并做零频率平滑与权重上限（防止 1/f 发散）。

### 2.2 分子：严重度 = 三条腿互相印证


| 腿   | 方法                      | 得到什么             | 依赖            |
| --- | ----------------------- | ---------------- | ------------- |
| 腿 1 | 实测人工修复耗时（每人每类只改一处，计时）   | 严重度**主值** + 置信区间 | 8–12 名参与者     |
| 腿 2 | 最小成对比较（两个版本只差一类缺陷，二选一）  | 严重度**排序**（交叉验证）  | 8–12 人 / 30 对 |
| 腿 3 | 语料里的越界幅度分布（不只看有没有，看多过分） | 严重度里可数据化的部分      | 现有语料          |




### 2.3 尺度锚定

`wᵢ` 只定义**相对尺度**：锚定 `w_overfull = 1.0`，绝对尺度由汇率 ρ 吸收。
（理由见 D4。这一点必须写进文档，否则"权重是多少"这个问题本身没有意义。）

## 3. 五项工作



### A. 形式层改造（不依赖任何外部数据，优先做）

1. **加饱和曲线**（解 D2）：`Σ wᵢ·nᵢ` → `Σ wᵢ·g(nᵢ)`，`g` 为边际递减函数
  （候选：`1-exp(-n/τ)` 或按页密度的分段线性）。
  - 依据：边际递减属常识级行为规律，无需实验即可论证。
  - `τᵢ` 可由语料的计数分布定（P50/P90），这一步可数据化。
2. **gate 分层**（解 D5，方案 B）：
  - 终止级（编译失败 / 无 PDF / 图表被改写）与可修级（页数 / 字号 / 边距 /
   fleqn / 目录 / 页眉）分开；级间有优先级，同级内部比条数。
  - 顺手删除 `core.py` 里现有的两个特判（编译失败硬拦、压页"页数不增即保留"），
  把语义收进分层规则本身。
3. **权重外置 + 版本化**（解 D6）：`PAGE_DEFECT_WEIGHT` / `SOFT_BANDS` /
  `HYGIENE_WEIGHT` / `VISUAL_DEFECT_M1` / ρ / β → JSON 权重文件；
   复用 `weights.py` 的 `weights_version` 机制，写进报告与 `state.json`。
4. **文档同步**（解 D4）：在公式文档中写明锚定规则与"只有比值有意义"。
5. 同步更新 `tests/run_tests.py`：锁住饱和行为、gate 分层语义、JSON 加载与默认值兜底。

**产出**：改造后的 `score.py` / `core.py` + 权重 JSON + 回归用例 + 文档更新。

### B. 分母：语料的「容忍度表」

**B1. 现有语料（608 篇 PDF，立即可跑）**

- 覆盖范围：仅**版面可观测**的类别（留白异常 / 图表覆盖 / 均衡 / 一致性 / 页框等）。
- **明确不含**：overfull、underfull、vbox、floatwarn —— 这些只有编译日志才有，
而语料 `doc.tex` 全为 `null`，`microtype.status` 608/608 为 `unavailable`。
- 产出：按 `venue × 角色 × 栏数` 的**越界率 + 分布表**，外加越界幅度列（供腿 3）。

**B2. 新增源码语料（需采集 + 编译，N≈300）**

- 流程：解压 → 定位主文件 → 本机 xelatex 编译 → 用既有 `perceive.parse_log()`
抽取 overfull/underfull/vbox/floatwarn 计数 → 汇总成频率表。
- 两份表层：**频次**（多少篇出现、篇均几处）+ **幅度**（越界多严重）。
- 预期编译成功率 ~70%（缺宏包、路径写死、外部依赖、安全限制），失败如实记录，不硬凑。



### C. 分子：严重度标定

- **腿 1 实验包**：12 类缺陷各埋一个最小可复现样例 + 计时表模板，可直接对外发放。
- **腿 2 工具改造**：复用 `datasets/conf-specs/tools/make_pairs.py` 的渲染 + 离线
HTML 打分表能力，把配对逻辑从"打分维度"改为"只差一类缺陷"的最小对照对。
- **腿 3**：从 B1/B2 的幅度列直接导出。
- 汇总：腿 1 定主值、腿 2 验排序、腿 3 给幅度；三者冲突时如实报告并查因。



### D. 汇率 ρ 的桥接标定

- 权重只能定比值，`ρ` 是"缺陷 ↔ 版面代价"的换算尺，属偏好，语料给不出。
- 做法：用腿 1 的耗时数据桥接 —— "改 4mm 边距 ≈ 人手动花 3 秒，
修一处溢出 ≈ 20 秒" → 给出 ρ 的合理区间，而不是拍一个 2.0。
- 现值 2.0 在文档中如实标注为"待标定的折中值"。



### E. 验证与收口

1. **检测器体检**：每个要进权重表的维度都必须通过"注入 → 感知 → 响应方向"检查
  （扩展现有 E4 `sensitivity_sweep`）。上次已抓出 2 个盲维
   （`alignment.center_var`、`ratio.fig_text`）——**盲维一律踢出权重表，只作报告项**。
2. **交叉验证**：B 的"常见度排序" vs C 的"严重度排序"，打架即查因。
3. **闭环自洽**：新权重与新 gate 分层下重跑靶稿与 page-limit 场景，
  确认不劣化 + 有界收敛，并复核 `chaotic_layout` 等已知出口状态变化是否合理。
4. **总表交付**：每类缺陷一行 —— 频率 / 越界幅度 / 人工耗时 / 成对排序 /
  最终权重 / 依据来源 / 是否通过检测器体检。

## 4. 分工与依赖

**可独立完成**：A 全部、B1、B2、C 的两个实验包与工具改造、D 的数据桥接、E 全部。

**需要用户提供**：

1. 腿 1 / 腿 2 的**参与者**（每组 8–12 人，各 15–20 分钟）；
2. 新源码语料**下载后告知路径**（建议近三年、有 arXiv 号、图表较多的论文）。

**顺序与依赖**：

```
A 形式改造（含 gate 分层） ──┐
                            ├─→ C 汇总 ─→ D ─→ E 收口 ─→ 总表
```

## 6. 风险与诚实边界（必须写进论文/汇报）

- **覆盖有限**：现有语料只能覆盖版面可观测类别；日志类缺陷必须靠新采源码语料。
- **频率 ≠ 重要性**：频率只作分母（归一化 + 容忍度代理），严重度另有来源。
- **检测器可靠性前置**：权重只能建在体检通过的维度上；已知存在可辨识性差的指标
（如 `whitespace.trailing_ratio` 全库仅 6.58% 非零，属**指标问题**而非真罕见）。
- **尺度不可辨识**：只定义相对权重，锚定 `w_overfull = 1.0`。
- **ρ 是偏好不是常数**：由人工标定桥接，不可声称"客观最优"。
- **共现重复计数**：overfull/underfull、vbox_under/stranded_block 同源，需查条件频率。
- **选择与时效偏差**：录用稿 ≠ 投稿稿；会议要求逐年变化，须按 venue×year 分组并做时间衰减。
- **gate 分层后的语义**：终止级/可修级是**设计约定**，需在文档中显式声明，
并说明它替代了原先的两处特判。
- **系统不声称全局最优**：只保证全局评分单调不劣化 + 有界收敛（沿用 README 口径）。
